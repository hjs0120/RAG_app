# Chunk 품질 진단 리포트

**대상 파일**: `output/이동식_해양구조물_규칙_2024_chunks.jsonl`  
**FAISS 검색 품질**이 만족스럽지 못한 원인 분석

---

## 1. 발견된 문제점

### 1.1 paragraph "0" 그룹 — 서로 다른 조문 혼합 (심각)

`paragraph: "0"`은 제목·머리말 등 paragraph가 없는 줄들을 모은 그룹입니다.

**예시 (chunk 5번)**:
```json
{"article": "10", "paragraph": "0", "text": "10. 과도한 부식... 10. 펌프의 압력... 10. 시험 보기... 10. 하중시험"}
```
- **pages**: [12, 68, 80, 83] — 서로 다른 4개 페이지
- "10. 과도한 부식" (두께계측)
- "10. 펌프의 압력" (소화설비)
- "10. 시험 보기" (선급규칙)
- "10. 하중시험" (갑판승강장치)

→ **서로 무관한 네 가지 조문이 한 chunk에 섞여 있음.**  
→ "제10조 검사 주기" 검색 시 과도한 부식·펌프·시험 보기 등 엉뚱한 내용이 함께 검색됨.

---

### 1.2 동일 article, 동일 paragraph — 다른 절(section) 혼합 (심각)

규칙 문서 구조: `101. 적용`, `101. 일반`, `101. 하중` 등은 **같은 101번이지만 서로 다른 절**입니다.

**예시 (chunk 10번)**:
```json
{"article": "101", "paragraph": "(1)", "text": "(1) 갑판하중 (1) 폐위구역이란... (1) 이 절의 규정은... (1) 구조물의 안전에..."}
```
- 101. 갑판하중의 (1)호
- 101. 폐위구역의 (1)호
- 101. 기관 적용의 (1)호
- 101. 정적경사조건의 (1)호
- …

→ **같은 article "101", paragraph "(1)"이라 하나로 merge되었지만, 실제로는 서로 다른 101.xxx 절들**이라 문맥이 뒤섞임.

---

### 1.3 너무 짧은 chunk

**예시**:
- `"(1) 공장시험"` — 7자
- `"1001. 일반"` — 8자
- `"(마) 평형수 주배수장치"` — 제목만

→ 검색 시 문맥 부족으로 임베딩 품질이 떨어질 수 있음.

---

### 1.4 원인 정리

| 원인 | 설명 |
|------|------|
| **Merge key 과단순화** | (doc_id, article, paragraph)만 사용. `101.적용`과 `101.하중`을 구분하는 section/chapter가 없음 |
| **paragraph "0" 의미** | "제목·머리말" 등 paragraph 없는 줄을 한 그룹으로 합침 → 서로 다른 절의 제목이 모여 혼합됨 |
| **원본 path 구조** | path에 `chapter`, `section`이 null. "101.적용"의 "적용"을 표현할 수 없음 |

---

## 2. 개선 방향

### 2.1 원본 파싱 단계 (권장)

- "101. 적용", "101. 일반" 등에서 **절 이름(section)**을 추출해 `path.section`에 저장
- Merge key에 `section` 포함: `(doc_id, article, section, paragraph)`
- 이렇게 하면 101.적용의 (1)과 101.일반의 (1)이 서로 다른 그룹으로 분리됨

### 2.2 Chunk 빌드 단계

- **paragraph "0" 그룹**: merge하지 말고 **한 줄 = 한 chunk**로 처리, 또는 해당 그룹 자체를 생성하지 않음
- **최소 길이**: 너무 짧은 chunk는 이전/다음 문단과 합치거나, 최소 문자 수 이하면 건너뜀

### 2.3 임시 조치

- Merge key를 바꾸지 않고, **paragraph "0" 그룹만 라인별로 분리**하는 방식으로라도 혼합을 줄일 수 있음

---

## 3. 요약

FAISS 검색이 만족스럽지 않은 주요 원인은 **청크에 서로 무관한 조문이 섞여 들어가는 것**입니다.

1. **paragraph "0"**: 제목·머리말 등이 전역에서 모여 한 chunk가 됨 → 혼합 심함  
2. **article+paragraph만 사용**: 101.적용의 (1)과 101.하중의 (1)이 동일 그룹으로 merge됨  
3. **원본 path 구조**: section/chapter 정보 부재로 세부 구분 불가  

해결을 위해서는 **원본 추출/파싱에서 section(절 이름)을 추출**하고, **Merge key에 section을 포함**하는 것이 근본적인 방법입니다.
